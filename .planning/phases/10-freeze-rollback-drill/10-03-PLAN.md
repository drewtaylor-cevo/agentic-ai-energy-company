## Two-commit pattern (NEW — fixes WN-2)

A commit's SHA is a hash of its content (including the manifest), so the manifest can't embed
its own commit's SHA up-front. Resolution — two commits:

1. Task 12: manifest has `git.freeze_commit_sha: "TBD"` (stub); do not commit
2. Task 13 step (a): commit the stub-bearing manifest → this commit has SHA_A (= `FREEZE_SHA`)
3. Task 13 step (b): `FREEZE_SHA=$(git rev-parse HEAD)`
4. Task 13 step (c): edit manifest replacing `"TBD"` with `"$FREEZE_SHA"`
5. Task 13 step (d): second commit → this commit has SHA_B (= `POST_AMEND_SHA`)
   - The tree of this commit has the self-referenced manifest naming SHA_A
6. Task 15: `git tag -a demo-v2.0 … $POST_AMEND_SHA`
7. Task 16 invariant: `git rev-list -n 1 demo-v2.0^ == manifest.git.freeze_commit_sha` (both == SHA_A)

Why this over `git commit --amend`: `--amend` rewrites the original commit, making SHA_A
dangling and unreachable from the tag. The two-commit pattern preserves SHA_A as `tag^` so the
manifest's self-reference targets a reachable commit.
