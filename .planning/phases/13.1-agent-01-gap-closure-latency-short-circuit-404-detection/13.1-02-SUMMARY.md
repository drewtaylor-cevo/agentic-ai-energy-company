## Decisions made during execution

**`_build_agent_result` refactor approach: split, not parameterise.**
Per plan recommendation option 1: split the legacy 3-tool helper into `_build_agent_result_shock` (Elena, 3 tools) and `_build_agent_result_non_shock` (Marcus, 2 tools). Rationale: the shape change is semantic (non-shock SHORT-CIRCUITs past detect_bill_shock), not just a count. Splitting makes the D-13.1-14 contract explicit in the function name and keeps each helper readable. Parameterising `tool_count=...` would have hidden the shape difference behind a magic integer.

**Plan 01 prompt iteration: none required.** The first run of `TestShortCircuit::test_non_shock_sarah_drives_2_tools_only` failed with `AssertionError: MockedModelProvider: prompt drove 4 model calls but only 3 scripted responses available` — but the root cause was NOT prompt drift. It was a D-15 validation failure on the terminal `call_script`: `"Ask about Value 12 — ..."` contains digit `12`, and `validate_call_script` rejects digits via `NUMERIC_REGEX`. Strands retried after validation failure, exhausting the scripted sequence. Fix was bounded to test fixtures (three call_script strings rewritten to drop "12" suffix); Plan 01's prompt text is unchanged.
