### Pattern 1: Strands canonical `MockedModelProvider(Model)` for prompt-level testing

**What:** Subclass the abstract `strands.models.Model` and script `Message` responses; the mock's `stream()` iterates a list and emits the right `StreamEvent` dicts per message.

**When to use:** Offline tests that need to exercise the REAL Strands decision loop + hooks + tool registry against a scripted model. Use when "prompt says X but Strands interprets as Y" is the class of bug under test (exactly Phase 13 Gap 1's root cause).

**Example (Strands' own canonical source):**

```python
# Source: https://github.com/strands-agents/sdk-python/blob/main/tests/fixtures/mocked_model_provider.py
import json
from collections.abc import AsyncGenerator, Iterable, Sequence
from typing import Any, TypedDict, TypeVar

from pydantic import BaseModel
from strands.models import Model
from strands.types.content import Message, Messages
from strands.types.event_loop import StopReason
from strands.types.streaming import StreamEvent
from strands.types.tools import ToolSpec

T = TypeVar("T", bound=BaseModel)


class MockedModelProvider(Model):
    """Mock implementation of the Model interface for testing purposes.

    Returns pre-defined agent responses in sequence. Implements Model interface
    methods and provides functionality to stream mock responses as events.
    """

    def __init__(self, agent_responses: Sequence[Message]):
        self.agent_responses = [*agent_responses]
        self.index = 0

    def get_config(self) -> Any: pass
    def update_config(self, **model_config: Any) -> None: pass

    async def structured_output(
        self, output_model: type[T], prompt: Messages,
        system_prompt: str | None = None, **kwargs: Any,
    ) -> AsyncGenerator[Any, None]:
        pass  # intentionally empty — forces force-tool path through stream()

    async def stream(
        self, messages: Messages, tool_specs: list[ToolSpec] | None = None,
        system_prompt: str | None = None, tool_choice: Any | None = None,
        *, system_prompt_content=None, **kwargs: Any,
    ) -> AsyncGenerator[Any, None]:
        events = self.map_agent_message_to_events(self.agent_responses[self.index])
        for event in events:
            yield event
        self.index += 1

    def map_agent_message_to_events(self, agent_message: Message) -> Iterable[dict[str, Any]]:
        stop_reason: StopReason = "end_turn"
        yield {"messageStart": {"role": "assistant"}}
        for content in agent_message["content"]:
            if "text" in content:
                yield {"contentBlockStart": {"start": {}}}
                yield {"contentBlockDelta": {"delta": {"text": content["text"]}}}
                yield {"contentBlockStop": {}}
            if "toolUse" in content:
                stop_reason = "tool_use"
                yield {"contentBlockStart": {"start": {"toolUse": {
                    "name": content["toolUse"]["name"],
                    "toolUseId": content["toolUse"]["toolUseId"],
                }}}}

                }}}}
                yield {"contentBlockStop": {}}
        yield {"messageStop": {"stopReason": stop_reason}}
```

## Common Pitfalls

### Pitfall 1: Mock-model stop_reason handling with `structured_output_model=…`

**What goes wrong:** Agent raises `"No valid tool use or tool use input was found"` because the scripted mock never emits the `RecommendationResponse` toolUse block with valid input.

**Why it happens:** `agent/agent.py:711-714` passes `structured_output_model=RecommendationResponse` to `_agent(...)`. Strands internally forces a tool-use round by appending the `RecommendationResponse` tool spec with `tool_choice={"any": {}}` — if the mock runs out of messages OR emits `end_turn` before the structured-output tool use, the happy path raises and invoke() falls through to the `except StructuredOutputException` OR the bottom `except Exception` branch.

**How to avoid:** Scripted mock MUST include a final assistant message carrying a `toolUse` block with `name == "RecommendationResponse"` and `input` that parses as the Pydantic schema. Example for CUST-001 2-tool happy path (3 scripted messages):

```python
scripted = [
    {"role": "assistant", "content": [
        {"toolUse": {"name": "get_hardship_flag", "toolUseId": "tu-1",
                     "input": {"customer_id": "CUST-001"}}}]},
    {"role": "assistant", "content": [
        {"toolUse": {"name": "simulate_savings", "toolUseId": "tu-2",
                     "input": {"customer_id": "CUST-001"}}}]},
    {"role": "assistant", "content": [
        {"toolUse": {"name": "RecommendationResponse", "toolUseId": "tu-3",
                     "input": {"green": {…}, "cheapest": {…}, "reasoning_trace": [...]}}}]},
]
```

**Warning signs:** Test fails with `ValueError("No valid tool use or tool use input was found in the Bedrock response.")` — trace back to either a missing final scripted message or a typo in the tool name (`RecommendationResponse` is case-sensitive).

### Pitfall 2: Mock-model index exhaustion vs IndexError semantics

**What goes wrong:** A non-shock test scripts ONLY 3 messages (hardship + simulate + RecommendationResponse). If the prompt incorrectly drives 4 calls (e.g., regresses to the Phase 13 3-tool path), the mock raises `IndexError` — but the assertion you wanted to fire ("too many tools called") never runs.

**Why it happens:** `MockedModelProvider.stream()` does `self.agent_responses[self.index]` without bounds checking.

**How to avoid:** Two options:
- (a) Script a 4th defensive message that would be an OBVIOUS violation (e.g., a 4th toolUse with a bogus `name`) and assert in the test that the mock's `.index == 3` afterward (i.e., the real prompt only consumed 3 messages).
- (b) Wrap the scripted list in a custom `MockedModelProvider` subclass that raises `AssertionError("prompt drove N+1 tools, expected ≤N")` on exhaustion.

**Recommendation:** Prefer (b) — cleaner failure message. The planner writes a ~10-LOC `StrictMockedModelProvider` in `tests/fixtures/` that subclasses `MockedModelProvider` and overrides `stream()` with a bounds check.

### Pitfall 3: Async event-loop wiring in offline tests

**What goes wrong:** Pytest fails with `RuntimeError: event loop is closed` or `AttributeError: 'NoneType' object has no attribute 'run_until_complete'` because Strands spins its own event loop internally.

**Why it happens:** `Agent.__call__()` → `Agent.invoke_async()` → internal `run_async()` helper that creates a fresh event loop. Works fine from a sync test function (standard pytest) but breaks if the test is already async-marked without proper `pytest-asyncio` wiring.

**How to avoid:** Write offline tests as SYNC functions (no `@pytest.mark.asyncio`). Call `agent("prompt")` directly — Strands handles the async internally. Matches the pattern used by Strands' own `tests/strands/agent/test_agent_hooks.py::test_agent__call__hooks`. Existing test_bill_shock_flow.py tests are already sync; continue the pattern.

### Pitfall 4: Mid-ceremony extractor-fix commit `5644003` is load-bearing

**What goes wrong:** Someone rebases / squashes / amends `5644003` to "clean up" the commit history; `_extract_reasoning_trace` reverts to iterating `agent_result.message['content']` instead of `_agent.messages[_messages_start:]`; live reasoning_trace goes empty again.

**Why it happens:** The commit looks cosmetic ("extractor reads _agent.messages slice, not agent_result.message") but is the actual fix for Strands 1.37's `AgentResult.message = LAST message only` behaviour.

**How to avoid:** Do not touch `5644003`. `tests/test_reasoning_trace_extractor.py` (if it exists) or `tests/test_bill_shock_flow.py::TestCrossPersonaCanary::test_end_to_end_reasoning_trace_differs_elena_vs_marcus` implicitly locks the extractor behaviour. Verify `git log --oneline | grep 5644003` shows the commit unchanged before every Wave 2 ceremony.

### Pitfall 5: CloudWatch metric emission lag on smoke tests

**What goes wrong:** `test_agent01_tools_actually_invoked` (D-21) runs in CI and reports `0 invocations` because the `time.sleep(90)` was shortened to save time.

**Why it happens:** CloudWatch emission is 60-90s lagged on the `Invocations` metric; shortening the sleep produces false negatives. Documented in `tests/test_narrative_eval_live.py:162` and `CLAUDE.md` Common-commands section.

**How to avoid:** DO NOT shorten the 90-second sleep. If CI is too slow for smoke tests, gate smoke by env var (which is already done — `BACKEND_API_URL` + `TOOLS_LAMBDA_NAME`). Offline-only CI runs `pytest -m "not smoke"`.

### Pitfall 6: Cosmetic CloudFormation trailing whitespace in freeze-JSON byte-equality

**What goes wrong:** Freeze re-apply "fails" byte-equality against `*-freeze.json` because CFN's `get-stack-policy` returns the JSON with an extra trailing `\n\n`.

**Why it happens:** CFN-side serialisation artefact; documented in `13-08-CEREMONY-LOG.md` line 80 (Phase 12 precedent).

**How to avoid:** Normalise trailing whitespace + strip empty lines before diff. Example pattern:

```bash
aws cloudformation get-stack-policy --stack-name CustomerTariffAgent \
  --query 'StackPolicyBody' --output text | tr -s '[:space:]' '\n' > /tmp/cfn-agent.txt
cat infrastructure/stack-policies/agentcore-freeze.json | tr -s '[:space:]' '\n' > /tmp/src-agent.txt
diff /tmp/cfn-agent.txt /tmp/src-agent.txt    # should be silent
```

### Pitfall 7: Planner may drop CustomerTariffApi from the lift if `cdk diff` accidentally reports 0

**What goes wrong:** Planner runs `cdk diff CustomerTariffApi` AFTER editing `api_lambda/handler.py:152`, but the handler asset bundle's hash hasn't been re-computed yet (stale `cdk.out/`), so diff reports 0. Planner drops the stack. Sentinel never ships.

**Why it happens:** `cdk.out/` caching + plan-time vs deploy-time staleness.

**How to avoid:** Planner (or operator at Wave 2 start) runs `rm -rf cdk.out/ && cdk diff CustomerTariffApi` before the lift decision. Both stacks (Agent + Api) expected to show non-zero diff. Per D-13.1-17: "Expected: BOTH stacks show a diff."

### Example 1: `StrictMockedModelProvider` for D-13.1-15 non-shock regression guard

```python
# tests/fixtures/mocked_model_provider.py  (NEW — or inline in conftest.py)
# Source: verbatim from https://github.com/strands-agents/sdk-python/blob/main/tests/fixtures/mocked_model_provider.py
#         + our own StrictMockedModelProvider subclass (<20 LOC) for D-13.1-15 bounds checking.
import json
from collections.abc import AsyncGenerator, Iterable, Sequence
from typing import Any, TypeVar

from pydantic import BaseModel
from strands.models import Model
from strands.types.content import Message, Messages
from strands.types.event_loop import StopReason
from strands.types.streaming import StreamEvent
from strands.types.tools import ToolSpec

T = TypeVar("T", bound=BaseModel)


class MockedModelProvider(Model):
    """Canonical Strands mock — scripted Message → StreamEvent dict sequence."""

    def __init__(self, agent_responses: Sequence[Message]):
        self.agent_responses = [*agent_responses]
        self.index = 0

    def get_config(self) -> Any: return {}
    def update_config(self, **model_config: Any) -> None: pass
    async def structured_output(self, output_model, prompt, system_prompt=None, **kwargs):
        pass  # intentionally empty — force-tool uses stream()

    async def stream(
        self, messages, tool_specs=None, system_prompt=None, tool_choice=None,
        *, system_prompt_content=None, **kwargs,
    ):
        if self.index >= len(self.agent_responses):
            raise AssertionError(
                f"MockedModelProvider: prompt drove {self.index + 1} model calls "
                f"but only {len(self.agent_responses)} scripted responses available. "
                f"Likely cause: prompt short-circuit not firing (Gap 1 regression)."
            )
        events = self._to_events(self.agent_responses[self.index])
        for event in events:
            yield event
        self.index += 1

    def _to_events(self, msg: Message) -> Iterable[dict[str, Any]]:
        stop: StopReason = "end_turn"
        yield {"messageStart": {"role": "assistant"}}
        for block in msg["content"]:
            if "text" in block:
                yield {"contentBlockStart": {"start": {}}}
                yield {"contentBlockDelta": {"delta": {"text": block["text"]}}}
                yield {"contentBlockStop": {}}
            if "toolUse" in block:
                stop = "tool_use"
                yield {"contentBlockStart": {"start": {"toolUse": {
                    "name": block["toolUse"]["name"],
                    "toolUseId": block["toolUse"]["toolUseId"],
                }}}}
                yield {"contentBlockDelta": {"delta": {"toolUse": {
                    "input": json.dumps(block["toolUse"]["input"])
                }}}}
                yield {"contentBlockStop": {}}
        yield {"messageStop": {"stopReason": stop}}
```
