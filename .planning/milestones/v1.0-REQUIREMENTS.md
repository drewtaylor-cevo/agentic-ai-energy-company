# Requirements Archive: Customer Tariff & Billing Optimisation Agent — v1.0

**Defined:** 2026-04-23
**Shipped:** 2026-04-25 (tag: `demo-v1.0`)
**Core Value:** A call centre agent can open any customer account and immediately see exactly how much that customer could save and on which plan — making every retention conversation data-driven.

All v1 requirements delivered. This file is the archived snapshot of `REQUIREMENTS.md` at milestone close.

## v1 Requirements — All Complete

### Data (DATA)

- [x] **DATA-01**: System retrieves 12 months of billing history per customer, including monthly kWh usage, monthly cost, and current tariff plan details — **Validated** in Phase 1 (`get_billing_history` returns 12 monthly records per persona from DynamoDB; 36 records total across 3 personas)
- [x] **DATA-02**: Dummy dataset covers at least 3 customer personas with meaningfully different usage profiles — **Validated** in Phase 1 (3 personas seeded: high-usage residential, medium-usage, low-usage/seasonal — distinct kWh profiles engineered to produce the DEMO-02 deltas)
- [x] **DATA-03**: Usage data stored in kWh (not dollars) to produce defensible savings calculations — **Validated** in Phase 1 (every billing record stores `usage_kwh` and `cost_usd`; savings recomputable independently)

### Recommendations (REC)

- [x] **REC-01**: Agent identifies and recommends the most energy-efficient (Green) tariff plan — **Validated** in Phase 2 (`simulate_savings` returns the greenest plan from the tariff catalog that also saves money vs current plan)
- [x] **REC-02**: Agent identifies and recommends the lowest projected cost (Cheapest) tariff plan — **Validated** in Phase 2 (`simulate_savings` returns the lowest-projected-cost plan; pytest invariant asserts `cheapest.saving >= green.saving` per persona)
- [x] **REC-03**: Both Green and Cheapest recommendations are always surfaced simultaneously — neither ranked above the other — **Validated** in Phases 2 and 4 (agent returns both keys in every response; UI renders two equal-weight cards side-by-side)

### Savings Simulation (SAV)

- [x] **SAV-01**: For each recommendation, agent displays projected monthly saving in dollars (~$X/month) against the customer's 12-month billing average — **Validated** in Phases 1 and 2 (`saving_monthly` calculated against 12-month average on current plan)
- [x] **SAV-02**: Annual equivalent saving ($X/year) displayed alongside the monthly figure — **Validated** in Phases 1 and 2 (`saving_annual = saving_monthly * 12`, surfaced on every card)
- [x] **SAV-03**: Savings calculated by a deterministic tool function — LLM handles orchestration and narrative, arithmetic is done in code — **Validated** in Phases 1 and 2 (`simulate_savings_pure` is a deterministic Python function; LLM invokes it via Strands `@tool`, never performs arithmetic)

### Agent-Assist UI (UI)

- [x] **UI-01**: Both recommendation cards visible above the fold in the call centre agent-assist interface — **Validated** in Phase 4 (Plan 04-05 human-verified 1280px smoke: both cards render above the fold, no scroll required)
- [x] **UI-02**: From customer account lookup to displayed recommendations renders in under 3 seconds — **Validated** in Phase 5 smoke-derived evidence (Plan 05-02 live pytest wall-clock ≲2s per request). Visual T-24h DevTools rehearsal scheduled per DEMO-RUNBOOK to confirm warm-median under real browser load.

### Demo (DEMO)

- [x] **DEMO-01**: End-to-end demo runs on dummy data with no live CRM connectivity required — **Validated** in Phase 3 (self-contained API) and re-verified in Phase 5 (Plan 05-04 no-CRM structural audit, D-16 code-path audit with re-runnable grep commands)
- [x] **DEMO-02**: Dummy data intentionally designed so Green track saves ~$30/month and Cheapest track saves ~$55/month per persona — **Validated** in Phase 1 (pytest locks flagship persona at $30 Green / $55 Cheapest; delta tells a clear story per persona)
