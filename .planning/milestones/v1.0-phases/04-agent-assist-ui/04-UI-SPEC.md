# Phase 4 — UI Design Contract

> Visual and interaction contract for the Agent-Assist UI (call-centre operator surface). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase scope: single-page operator tool. Operator enters a customer ID, sees two tariff recommendations side-by-side (Green track + Cheapest track), can read the short methodology line for each, and copy or relay the recommendation to the customer. Backend is the API from Phase 3.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn |
| Preset | New York style, Slate base, CSS variables on (`style: new-york`, `baseColor: slate`, `cssVariables: true`) |
| Component library | radix (via shadcn/ui primitives) |
| Icon library | lucide-react |
| Font | Inter (Google Font, weights 400 + 600, `font-display: swap`) |

Initialization note: shadcn/ui has not yet been initialized in this repo (no `components.json` present at the time of spec). The executor MUST run `npx shadcn@latest init` with the preset above as the first setup task in Phase 4. Tailwind CSS is assumed to be configured via the shadcn init flow.

Components expected to be pulled from shadcn official: `button`, `input`, `card`, `label`, `skeleton`, `alert`, `badge`. Additional primitives only if justified in the plan.

## Spacing Scale

Declared values (multiples of 4, mapped 1:1 to Tailwind defaults):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gap inside badges, tight inline spacing |
| sm | 8px | Compact element spacing (label-to-input, badge padding) |
| md | 16px | Default element spacing inside cards, form gap |
| lg | 24px | Card internal padding, section padding |
| xl | 32px | Gap between the two recommendation cards, form-to-results gap |
| 2xl | 48px | Major section breaks (header-to-form, form-to-results on desktop) |
| 3xl | 64px | Page-level vertical rhythm (top of app, below results) |

Exceptions: none. Primary CTA and input height standardize to 40px (shadcn default `h-10`), which is not a spacing-scale value but a fixed control size and does not count against the scale.

## Typography

Font family: `Inter, ui-sans-serif, system-ui, sans-serif`. Two weights only (400 regular, 600 semibold). Four sizes.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 (24px) |
| Label | 14px | 600 | 1.4 (20px) |
| Heading | 20px | 600 | 1.3 (26px) |
| Display | 28px | 600 | 1.2 (34px) |

Role mapping for this phase:
- Display: page title "Tariff Recommendations" (top of app).
- Heading: the per-card track heading ("Green Option" / "Cheapest Option") and section labels inside cards ("Recommended plan", "Estimated annual cost").
- Body: methodology line, plan description, error messages, empty-state body.
- Label: form labels ("Customer ID"), button text, badge text, small meta text (e.g., "100% renewable").

## Color

60/30/10 neutral palette built on shadcn New York + Slate CSS variables. Accent is reserved to encode track identity — this is the load-bearing visual decision for REC-03.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (light) / `#0F172A` (dark, `slate-950`) | App background, page surface |
| Secondary (30%) | `#F1F5F9` (light, `slate-100`) / `#1E293B` (dark, `slate-800`) | Card surfaces, input backgrounds, subtle containers |
| Accent — Green track (10%) | `#16A34A` (emerald-600) | Green card header band, Green card icon, Green badge "100% renewable" |
| Accent — Cheapest track (10%) | `#2563EB` (blue-600) | Cheapest card header band, Cheapest card icon, Cheapest badge "Lowest unit price" |
| Destructive | `#DC2626` (red-600) | 4xx/5xx error alert border + icon only |

Accent reserved for (explicit list, nothing else):
- Green track card: top border/header accent strip, track icon (lucide `Leaf`), "100% renewable" badge, and the "Recommended plan" value text color.
- Cheapest track card: top border/header accent strip, track icon (lucide `PiggyBank` or `DollarSign`), "Lowest unit price" badge, and the "Recommended plan" value text color.
- Primary CTA ("Look up customer"): uses the shadcn default `primary` (neutral slate) — NOT either track accent. Track accents are reserved exclusively to encode which track the user is reading, so they never appear on the form.

Card-layout contract (locked decision from discussion): both recommendation cards MUST use an identical layout — same width, same padding, same internal hierarchy, same row order, same typography. The ONLY permitted visual differences between the two cards are:
1. Accent color (emerald-600 vs blue-600) on the header strip, icon, badge, and recommended-plan value.
2. Heading text ("Green Option" vs "Cheapest Option").
3. Icon glyph (`Leaf` vs `PiggyBank`).
4. Methodology line text (per Copywriting Contract).

No other visual weighting (size, elevation, position emphasis, bold treatment) is allowed to imply one option is preferable over the other. This preserves operator neutrality between the Green and Cheapest recommendations.

Contrast: all text on secondary surfaces must meet WCAG AA (4.5:1 for body, 3:1 for large text). Accent colors are used for non-text emphasis and on text only where the shade is dark enough against white — emerald-600 and blue-600 both pass 4.5:1 on `#FFFFFF`.

## Copywriting Contract

All user-facing strings are owned by the UI layer. The API returns plan data only; the UI composes these strings.

| Element | Copy |
|---------|------|
| Page title | Tariff Recommendations |
| Form label | Customer ID |
| Form placeholder | e.g. CUST-001234 |
| Primary CTA | Look up customer |
| Primary CTA (loading) | Looking up… |
| Empty state heading | No customer selected |
| Empty state body | Enter a customer ID to see tariff recommendations. |
| Green track heading | Green Option |
| Green track badge | 100% renewable |
| Green track methodology | Based on your 12-month kWh usage at the {plan_name} rate (100% renewable). |
| Cheapest track heading | Cheapest Option |
| Cheapest track badge | Lowest unit price |
| Cheapest track methodology | Based on your 12-month kWh usage at the {plan_name} rate (lowest unit price). |
| Error 400 (bad input) | That doesn't look like a customer ID. Format is CUST followed by 3–6 digits. |
| Error 404 (not found) | No customer found for {id}. Check the ID and try again. |
| Error 504 (timeout) | Recommendations are taking longer than expected. Try again in a moment. |
| Error 500/502 (server) | Something went wrong on our end. Try again — if it persists, contact support. |
| Destructive confirmation | not applicable — Phase 4 has no destructive actions (read-only recommendation viewer). |

Templating rules:
- `{plan_name}` is substituted from the API response's per-track plan object. If `plan_name` is missing or empty, fall back to "selected" — e.g., "Based on your 12-month kWh usage at the selected rate (100% renewable)."
- `{id}` in the 404 error is the ID the operator submitted, echoed verbatim, trimmed and uppercased to match the canonical format.
- Methodology line is UI-owned and static per track. It is NOT read from the API, so the API adding/removing methodology fields has no effect on the UI contract.

Tone: direct, operator-facing, no marketing language. Errors tell the operator what went wrong AND what to do next in the same sentence.

## Interaction States (reference for executor)

Non-normative, derived from the contract above — included so the executor does not re-invent states:

- **Idle / empty:** form visible, empty-state message shown where results would render.
- **Loading:** CTA label swaps to "Looking up…", CTA disabled, two `Skeleton` placeholders render in the exact shape of the two result cards (same width, same height) to prevent layout shift and to reinforce the equal-cards contract even during load.
- **Success:** two cards render side-by-side on ≥768px viewport, stacked vertically on <768px. Card order: Green first, Cheapest second (stable — operator can learn positions).
- **Error:** shadcn `Alert` with `destructive` variant renders in place of (not in addition to) result cards, using the copy from the error table above keyed by HTTP status.
- **Re-query:** submitting a new ID clears previous results before the new request resolves (no stale data shown during loading).
