# Milestone v1.0: MVP

**Status:** ✅ SHIPPED 2026-04-25
**Phases:** 1–5
**Total Plans:** 21

## Overview

Initial release of the Customer Tariff & Billing Optimisation Agent — a call centre agent-assist demo that turns a customer account lookup into an instant, personalised tariff savings recommendation. Delivered as a fully self-contained, live AWS-deployed stack (Bedrock AgentCore + Lambda + API Gateway + React/Vite UI) running on engineered dummy data and locked behind the annotated `demo-v1.0` git tag.

Built strictly bottom-up: dummy data before the agent, agent before the API, API before the UI, full stack rehearsed before any live presentation. Five phases, each with a hard gate before the next began.

## Phases

### Phase 1: Foundation + Dummy Data

**Goal:** AWS infrastructure is standing and engineered dummy data drives correct, defensible savings calculations without any AI involvement.
**Depends on:** Nothing (first phase)
**Requirements:** DATA-01, DATA-02, DATA-03, DEMO-02
**Plans:** 3

- [x] 01-01-PLAN.md — CDK scaffold, tariff catalog JSON (4 plans at verified rates), and 36-record billing seed module (3 personas × 12 months, Python + DynamoDB wire format)
- [x] 01-02-PLAN.md — Lambda handler with `simulate_savings_pure` + `get_billing_history`, TDD pytest suite (29 tests) proving DEMO-02 flagship targets $30/$55 and V5 input validation
- [x] 01-03-PLAN.md — CDK constructs (BillingTable, ToolsLambda, Seeder) + FoundationStack wiring + offline synth tests + post-deploy smoke tests with human-verified cdk deploy

**Details:** 12-month billing history in kWh for 3 personas; deterministic savings engine in code (LLM handles orchestration and narrative, arithmetic in code); spreadsheet-verified Green $30/mo and Cheapest $55/mo delta for the flagship persona.

### Phase 2: AgentCore Agent

**Goal:** The Strands SDK agent orchestrates tool calls correctly and returns accurate Green and Cheapest recommendations for every demo persona.
**Depends on:** Phase 1
**Requirements:** REC-01, REC-02, REC-03, SAV-01, SAV-02, SAV-03
**Plans:** 3

- [x] 02-01-PLAN.md — Agent source code (Strands `@tool` + `BedrockAgentCoreApp` + Pydantic schema), Dockerfile (linux/arm64), and offline test suite (tool shape + savings invariants)
- [x] 02-02-PLAN.md — CDK infrastructure (SSM cross-stack wiring, `AgentCoreStack` with L2 Runtime construct, IAM policies, offline synth tests)
- [x] 02-03-PLAN.md — Deploy both stacks + live smoke tests via `invoke_agent_runtime` for all 3 personas (human-verify checkpoint)

**Details:** Strands SDK + `BedrockAgentCoreApp` pattern chosen over classic Bedrock Agents action groups — simpler for demo iteration, fewer IAM wiring steps. Both Green and Cheapest surfaced simultaneously; cheapest saving always ≥ green saving verified per persona.

### Phase 3: Backend API

**Goal:** A Lambda + API Gateway endpoint accepts a customer ID and returns streaming recommendations, making the demo fully self-contained with no live CRM dependency.
**Depends on:** Phase 2
**Requirements:** DEMO-01
**Plans:** 3

- [x] 03-01-PLAN.md — API Lambda handler (D-12 error taxonomy, D-11 fresh `uuid4` session, botocore 25s timeout) + 24-case offline unit test suite

## Milestone Summary

### Decimal Phases

None. All phases integer-numbered 1–5.

### Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Call centre agent-assist first (not customer-facing) | Reduces scope, controls UX, faster to demo | ✓ Good — panel delivered in Phase 4 against UI-01/UI-02 |
| Two fixed recommendation tracks (Green / Cheapest) | Keeps the recommendation scannable; avoids decision paralysis | ✓ Good — both cards above the fold, neither ranked |
| 12-month billing window for savings simulation | Smooths seasonal variation; easy to explain | ✓ Good — pytest locks DEMO-02 deltas across personas |
| Recommendation-only (no auto-switching) | Trust and compliance — human confirms before anything changes | ✓ Good — matches call centre workflow |
| Dummy data for demo | Controls the narrative; no integration risk for the POC | ✓ Good — no-CRM structural audit passed in 05-04 |
| Strands SDK / `BedrockAgentCoreApp` pattern (not classic Bedrock Agents action groups) | Simpler iteration, fewer IAM wiring steps | ✓ Good — single AgentCore stack, live smoke passes |
| kWh-based billing records (not dollars) | Defensible savings calculations that survive customer scrutiny | ✓ Good — arithmetic independently recalculable |
| 5-phase bottom-up build order | Data before tools, tools before agent, agent before API, API before UI | ✓ Good — every gate held |
| DEMO-02 assigned to Phase 1 | Savings delta must be engineered into dummy data before any agent work | ✓ Good — flagship $30/$55 locked pre-agent |
| Phase 3 live deploy deferred to Phase 5 | Stack lands on AWS once, cleanly, behind the demo tag | ✓ Good — single `cdk deploy` in 05-02, no thrash |
| Dual production dists (primary + mock fallback) | D-07 <10s emergency swap gate without network dependency | ✓ Good — both dists regeneratable from committed sources |
| Smoke-derived rehearsal (Plan 05-05) substituted for visual D-14/D-15 rehearsal | Didn't fabricate DevTools numbers; scheduled visual at T-24h per DEMO-RUNBOOK | — Pending until T-24h visual rehearsal |
| Don't commit build output (`ui/dist/`) | Reproducibility from sources, not artefacts; `.gitignore` enforced | ✓ Good — reproducibility gate validates regeneration |
