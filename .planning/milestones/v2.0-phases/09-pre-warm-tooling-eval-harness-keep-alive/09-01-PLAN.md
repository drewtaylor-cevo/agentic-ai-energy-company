    **Implementation flow (in `main()` after the env-var check):**

    Step 1 — **Warm pass (D-02 step 1).** Iterate PERSONAS in order. For each persona:
      a. Record `t0 = time.perf_counter()`.
      b. Call `urllib.request.urlopen(f"{api_url}/recommendations/{persona}?prewarm=1", timeout=HTTP_TIMEOUT_S)` inside a `with` block. Use the standard `Request` object if you need headers; `User-Agent` header is optional (the Lambda accepts anonymous clients).
      c. Read `resp.status` (stdlib `http.client.HTTPResponse.status`). Discard body.
      d. Compute `elapsed_ms = int((time.perf_counter() - t0) * 1000)`.
      e. Print to stdout in the EXACT format from D-04 (space-separated, lowercase verdict token):
         ```
         prewarm CUST-001: 204 312ms ok
         ```
         Use `print(f"prewarm {persona}: {resp.status} {elapsed_ms}ms ok")`.
      f. If `resp.status != 204`: print summary line `print(f"prewarm {persona}: {resp.status} {elapsed_ms}ms FAIL (expected 204)")` (stdout — this is a regular failure, not a setup error), then `return 1` — fast-fail before the measurement pass per D-02 step 1 last sentence.
      g. **D-06 taxonomy branch for setup errors:** Catch `(urllib.error.URLError, ConnectionRefusedError, socket.gaierror, socket.timeout)` on THE FIRST persona only (`persona == PERSONAS[0]`) → print `f"cannot reach {api_url}: {exc}"` to stderr and `return 2`. On any later persona, or on `urllib.error.HTTPError` (which has a status code — not a connectivity problem), treat as a runtime failure → print `prewarm {persona}: ERROR {exc}` and `return 1`.
      h. After each warm call except the last, `time.sleep(PREWARM_SPACING_S)`.

    Step 2 — **Wait (D-02 step 2).** Print `print("(wait 30s)")` to stdout (matches D-04 sample block exactly), then `time.sleep(SETTLE_WAIT_S)`. DO NOT reduce or make configurable — 30s is load-bearing per specifics line 261.

    Step 3 — **Measurement pass (D-02 step 3).** Build a dict `medians: dict[str, list[int]] = {persona: [] for persona in PERSONAS}`. For each persona in order, run `MEASUREMENT_SAMPLES` timed calls:
      a. Record `t0 = time.perf_counter()`.
      b. `with urllib.request.urlopen(f"{api_url}/recommendations/{persona}", timeout=HTTP_TIMEOUT_S) as resp:` — NO `?prewarm=1` on this pass.
      c. Read `resp.status`, read body (discard — `resp.read()` so the connection is consumed cleanly).
      d. `elapsed_ms = int((time.perf_counter() - t0) * 1000)`.
      e. Log line: `print(f"{persona} warm {i+1}/3: {elapsed_ms}ms {resp.status} {'ok' if resp.status == 200 else 'FAIL'}")` — D-04 verbatim (note the index is 1-based in the output).
      f. If `resp.status != 200`: append `elapsed_ms` to medians anyway (so the median stays truthful), then after the inner loop `return 1` per D-06 — do not silently continue past a non-200.
      g. **Timeout handling (D-08):** Wrap the `urlopen` + `resp.read()` in `try/except (socket.timeout, urllib.error.URLError)`. On timeout, print `f"{persona} warm {i+1}/3: TIMEOUT"` and append `MEDIAN_GATE_MS` (3000) to `medians[persona]` per D-08 last sentence ("treated as a ≥3000ms sample for median purposes"). Do NOT `return` — let the median push the gate to fail naturally.

    Step 4 — **Gate (D-02 step 4 + D-04 summary block).** Print the separator `print("---")`. For each persona in order, compute `median_ms = int(statistics.median(medians[persona]))` and print:
      ```
      median CUST-001: 1843ms PASS (<3000ms)
      ```
      (`PASS (<3000ms)` if `median_ms < MEDIAN_GATE_MS`, else `FAIL (≥3000ms)`.) Track `any_fail = any(median >= MEDIAN_GATE_MS for median in ...)`.

    Step 5 — **Exit summary line + return code.** If any persona failed the gate, print `print(f"{failed_persona} failed — exit 1")` and `return 1`. Else print `print("all personas under gate — exit 0")` per D-04 final line and `return 0`. Optional Claude's Discretion addition (recommended per CONTEXT.md line 151): print `print(f"total: {total_runtime_s:.1f}s")` as the VERY LAST line before return — measure via `t_start = time.perf_counter()` at the top of `main()`. Keep the `total:` line AFTER the `exit 0`/`exit 1` summary so it's visible but doesn't change the gate line semantics.
