What's reused from the agent-assist build

  • same APIGET /recommendations/CUST-001 — identical response shape, byte-identical dollar values ($30/mo, $55/mo, $360/yr, $660/yr)
  • same LLMNarrative + "Why this plan" strings returned by Claude Sonnet 4.6 through Bedrock AgentCore — same Pydantic validator rejecting digits, currency, banned terms
  • same kill switch?narrative=off URL flag collapses narrative + "Why this plan" to a digits-only card if the LLM layer misbehaves — no redeploy needed
  • same freezeBehind the demo-v2.0 tag: deny-Update:* CFN stack policies, DynamoDB backup, 5-step rollback drill passed

What's new in this surface

  • newCustomer authentication — OIDC/MFA, session scoping, PII handling. The current agent-assist build has zero auth; this is the load-bearing addition.
  • newMobile-first responsive layout (375–428px). Agent-assist is fixed at 1280×800.
  • newSelf-serve action — "Switch to EcoFlex" CTA replaces the call-centre agent reading the script aloud. Requires plan-change workflow, confirmation, and email receipt.
  • newRate limiting — a human reading this can't spam the API; an authenticated mobile app can.

What stayed deliberately off the screen

  • No ranking between Green and Cheapest — the customer chooses, same as the call-centre framing (REC-03).
  • No "you should switch" language — the Why this plan copy stays descriptive, not prescriptive. The Pydantic validator's banned-terms list (competitor names, switch verbs, environmental superlatives) still applies.
  • No digits or currency symbols in the narrative or "Why this plan" fields — the validator rejects these end-to-end regardless of which surface is consuming the API.
